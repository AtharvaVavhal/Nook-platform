## Proposed architecture

### MVP definition

**In:** staff sign in; an organisation's staff manage that organisation's properties, floors, rooms and beds; every read and write is tenant-scoped and audited; isolation is proven by a negative test suite against a real PostgreSQL; the 2D floor plan reads real inventory (read-only) if `D-3` includes the layout tables.
**Out, by decision or gate:** residents, stays, bookings and holds, availability computation, rent, payments, deposits, documents, imports, platform admin, any shared environment, deployment, real data.

### Ground rules for all code

1. **Explicit `@Inject(Token)` on every constructor parameter** (finding F-1). A `tsx` test asserts the app context resolves.
2. Exact version pins only; each new package its own commit, followed by `npm audit` and `npm audit signatures`.
3. The scope guard (`D-4`) and its self-tests land **before** the first model.
4. Repositories take a tenant context as their first argument; the Prisma client is importable only from repositories (lint rule). No raw SQL outside reviewed migrations.
5. Foreign keys say `onUpdate: Restrict` and `onDelete: Restrict` explicitly (finding F-4).
6. Tests use Node's test runner and global `fetch` against a real app instance; no new test dependency.
7. Migrations are created and applied only against `nook_dev` or `nook_test` through the tooling guard. Never port 5432.
